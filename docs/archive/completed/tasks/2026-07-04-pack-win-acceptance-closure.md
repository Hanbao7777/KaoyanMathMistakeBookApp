# Windows 打包验收闭环任务

## Background

错题本主线当前真实 P0 之一是“打包版验收闭环”。

现状已经确认：

- `package.json` 中存在 `pack:win`
- 本地 `typecheck` / `build` / CI 已稳定通过
- 仓库内没有当前有效的打包验收 checklist
- 已知 `ELECTRON_RUN_AS_NODE` 会影响 exe 双击启动

因此当前问题不是“能不能打包”，而是“如何稳定验收并留下可复用的验收流程”。

## Goal

建立错题本主线的 Windows 打包验收闭环文档，明确打包前准备、打包命令、人工验收步骤、结果记录方式。

## Non-Goals

- 不修改业务功能代码
- 不扩展到 TickTick 详细验收
- 不实现自动化 Windows E2E
- 不处理 P1 功能打磨

## Scope

- `package.json` 的 `pack:win` 现状核对
- 打包前环境检查
- 打包后错题本主链路人工验收清单
- 验收结果留痕方式

## Constraints

- 验收清单必须以当前仓库真实主线为准
- 只覆盖错题本主链路，不把 TickTick 全量验收混进来
- 需包含 `ELECTRON_RUN_AS_NODE` 的环境清理提示
- 文档必须可直接供后续人工执行

## Proposed Approach

1. 先写一份最小可执行打包验收清单。
2. 清单覆盖三段：
   - 打包前检查
   - 打包与产物确认
   - 错题本主链路人工验收
3. 明确验收结果应记录到哪里，避免“跑过但没留痕”。

## Risks

- 如果清单过宽，会把 TickTick 收口重新混入主线 P0
- 如果清单过窄，会遗漏启动、导入、复习、详情等核心链路
- 当前环境无法代跑 Windows GUI，只能先把流程文档标准化

## Acceptance Criteria

- 产出一份可执行的 Windows 打包验收清单文档
- 文档包含启动环境清理、打包命令、产物确认、主链路验收步骤、结果记录建议
- 清单聚焦错题本主线，不展开 TickTick 全量验收

## Task Breakdown

1. 盘点打包现状与已知风险
2. 编写打包验收 checklist
3. 明确留痕位置与执行顺序
4. 自审是否混入非主线内容

## Verification

- 对照 `package.json`、`KNOWN_ISSUES.md`、`ROADMAP.md`
- 人工检查清单是否可直接执行

# 错题本主线 Windows 打包验收 Checklist（可直接照做）

> 适用范围：**错题本主线**（错题管理 / 复习 / 知识地图 / 题库 / 备考监督 / 数据管理 / AI-OCR 入口）。
> TickTick 模式仅做“能进入、不崩溃”冒烟，**全量验收非本轮范围**，详见 [TICKTICK_KNOWN_BUGS.md](../../../../TICKTICK_KNOWN_BUGS.md)。
> 环境：Windows 10/11 x64。每次发布候选打一次，逐项打勾并留痕。

## 阶段 0：打包前准备

- [ ] 确认在项目根目录，分支/commit 记录清楚（`git rev-parse --short HEAD`）。
- [ ] 依赖干净安装：`npm install`（若曾报 Rollup 可选依赖缺失，删 `node_modules` 后重装，见 [KNOWN_ISSUES.md](../../../../KNOWN_ISSUES.md) 构建环境节）。
- [ ] 前置门槛全绿（任一失败则不打包）：
  - [ ] `npm run typecheck`
  - [ ] `npm test`
  - [ ] `npm run build`
- [ ] 备份/隔离真实数据目录：默认数据目录为 `D:\KaoyanMathMistakeBook`。验收建议用**干净数据目录**（临时改名或换机），避免污染真实错题库，也能顺带验证首启初始化。

## 阶段 1：启动环境清理（`ELECTRON_RUN_AS_NODE`）

> 已知坑：若 shell/系统继承了 `ELECTRON_RUN_AS_NODE`，exe 双击无窗口或进程一闪而过（[KNOWN_ISSUES.md](../../../../KNOWN_ISSUES.md)）。

- [ ] 当前 PowerShell 会话清理：`$env:ELECTRON_RUN_AS_NODE = $null`
- [ ] 检查系统环境变量中无残留 `ELECTRON_RUN_AS_NODE`（用户级/系统级都看）。
- [ ] 用于验收 exe 的窗口/终端就是完成上述清理的那个，避免换窗口后变量复现。

## 阶段 2：打包与产物确认

- [ ] 执行打包：`npm run pack:win`（脚本 = `npm run build && electron-builder --win portable --x64`）。
- [ ] 产物位置确认：`electron-builder` 输出目录为 `release/`（`package.json > build.directories.output`）；`pack:win` 目标为 **portable exe**（单文件便携版），确认 `release/` 下生成对应 `.exe`。
- [ ] 记录产物文件名与体积，确认非 0 字节、可复制到目标机。
- [ ] 冷启动验证：**双击** portable exe（不经由已配置环境的开发终端），确认弹出 GUI 主窗口而非无反应/闪退。

## 阶段 3：错题本主链路最小人工验收

> 每项只验“能打开 + 关键操作生效 + 无报错空白”。发现问题记录现象与复现路径，不在验收中顺手改代码。

- [ ] **首启/初始化**：干净数据目录首次启动，自动创建目录结构，内置考点种子（56 个：高数 43 + 线代 13）导入成功，Dashboard 可打开。
- [ ] **错题录入**：新增一道错题（题目/错误思考/正确解析/答案/分类/难度等），保存后在错题库可见。
- [ ] **错题库筛选/搜索**：多维度筛选、搜索、标签、排序可用，列表不空白。
- [ ] **错题详情**：打开详情，图片画廊、KaTeX 公式渲染、复习记录、知识点关联正常。
- [ ] **结构化导入**：导入 `wrong_questions_import.zip`（Excel+图片）走通预览→校验→批量图片复制；导入批次可见。
- [ ] **复习系统**：至少跑通 1 种复习模式（今日/薄弱/随机/按知识点），提交结果后掌握度与下次复习时间更新；撤销（5 秒内）生效。
- [ ] **知识地图**：树形目录 + 图谱视图可打开，知识点详情正常；PDF 页码提示/复制可用（**不要求外部阅读器自动跳页**）。
- [ ] **外部题库**：导入 `question_bank_import.zip`，刷题模式可用，可一键加入错题本。
- [ ] **备考监督**：监督中心、每日计划、专注计时、每日复盘可打开并完成一次基本操作。
- [ ] **统计与诊断**：Dashboard 与诊断中心各图表正常渲染。
- [ ] **数据管理**：手动备份成功；恢复前自动生成 `before_restore` 保护备份；JSON 导出/导入可用。
- [ ] **AI/OCR 入口（Beta，按需）**：未配置 DeepSeek Key / 未装 Python 时，入口有可读提示而非崩溃；如已配置，拍照导入→OCR→AI 结构化走通一次。
- [ ] **TickTick 冒烟（非本轮范围）**：一键切换到任务模式能进入、不崩溃即可，不做功能验收。

## 阶段 4：验收记录 / 留痕

- [ ] 在本文件下方“验收记录”表追加一行（日期 / commit / 产物文件名 / 结果 / 备注），保证“跑过且留痕”。
- [ ] 未通过项：记录现象、复现步骤、影响链路，另开子任务修复，不在验收文档里改代码。
- [ ] 通过后可据此更新 `ROADMAP.md` 顶部“打包版验收闭环”状态。
